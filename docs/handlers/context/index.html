Handler context

The full API of the ctx object that every handler receives.

Every handler receives a ctx object as its first argument. Its type depends on the route kind, so ctx.options only exists on slash commands and ctx.update only exists on buttons, selects and modals.

Which context each handler gets

HandlerContext typeAdds to the interaction context
defineCommand executeCommandContextoptions
defineUserCommand executeUserCommandContexttarget, targetMember
defineMessageCommand executeMessageCommandContexttarget
defineButton executeButtonContextparams, message, update, deferUpdate
defineSelect executeSelectContextparams, values, message, update, deferUpdate, plus resolved values for the select type
defineModal submitModalContextparams, values, fields, update, deferUpdate. It has no showModal.
Option autocompleteAutocompleteContextExtends the base context only. See Autocomplete context.
defineEvent execute, defineTask executeEventContext, TaskContextNothing. Both are the base context.

Base context

Events, tasks and every interaction handler share these fields.

FieldTypeMeaning
clientClient<true>The discord.js client.
appAppContextThe value from src/context.ts.
loggerLoggerA logger scoped to this route's id.
featurestringThe feature folder name.
routestringThe route id, such as mod warn or general/refresh.
shardsShardHelpersid, ids, count, fetchClientValues and broadcastEval. See Sharding.
commandsreadonly CommandInfo[]The enabled slash and context menu commands, sorted by name. See Listing commands.

Logger has level, debug, info, warn, error and child(scope). Every log method takes a message and any number of details. Tokens are redacted from the output.

Listing commands

ctx.commands lists the commands this bot registers, so a /help command does not need its own list. Commands in a disabled feature are left out.

FieldTypeMeaning
kind"command", "user-command" or "message-command"The command type.
namestringThe full name, such as mod warn. Context menu commands use their name.
descriptionstring | nullnull for context menu commands.
featurestringThe feature folder name.
guildOnlybooleanWhether it is limited to servers.
permissionsreadonly PermissionsString[]The required permissions.

Interaction context

Commands, context menus, buttons, selects and modals add these fields.

FieldTypeMeaning
kindInteractionKind"command", "user-command", "message-command", "button", "select" or "modal".
interactiondiscord.js interactionThe raw interaction, typed for the route.
guildGuild | nullNon-null in the types when guildOnly: true.
memberGuildMember | nullNon-null in the types when guildOnly: true.
userUserThe user who triggered the interaction.
stateRecord<string, unknown>A fresh object for each interaction, shared along the middleware chain and with the handler.
reply(node, options?)Promise<void>Replies, edits after a defer, or follows up. See Replying.
editReply(node, options?)Promise<void>Edits the reply.
followUp(node, options?)Promise<void>Sends another message. After a defer, it fills in the deferred reply instead.
defer(options?)Promise<void>Acknowledges now. options is { ephemeral?: boolean }. A no-op if already acknowledged.
deleteReply()Promise<void>Deletes the reply.
showModal(route, params?)Promise<void>Opens a modal route. It must be the first response. Not on modal contexts.

ReplyOptions is { ephemeral?: boolean; layout?: boolean }.

Do not call ctx.interaction.reply or its siblings yourself, because that bypasses layouts. The no-direct-interaction-reply rule reports it. Reading from ctx.interaction is fine.

Guild and member

With guildOnly: true, the type of ctx.guild and ctx.member loses null. At runtime, neocord fetches them if the interaction did not include them, and replies ephemerally with "This can only be used in a server." when they cannot be resolved. The handler does not run in that case.

The literal true is what narrows the type, because the helper captures it as a const type parameter. guildOnly: isGuild with a boolean variable keeps the nullable types.

Command context

ctx.options holds the resolved values, typed from the options object. See Options.

Context menu context

UserCommandContext has target: User and targetMember. targetMember is GuildMember | null, because the target may not be in the server even with guildOnly: true. MessageCommandContext has target: Message. See Context menus.

Component context

Buttons and selects add these fields.

FieldTypeMeaning
paramsRouteParams<R>Params from the route literal. [id] is a string, and [...rest] is a string[].
messageMessageThe message the component is on.
update(node, options?)Promise<void>Updates that message.
deferUpdate()Promise<void>Acknowledges without a visible loading state.

FieldTypeMeaning
paramsRouteParams<R>Params from the route literal.

Autocomplete context

An autocomplete handler receives the base context plus these fields. It cannot reply, and it returns choices instead. Middleware does not run for autocomplete.

FieldTypeMeaning
kind"autocomplete"Always this literal.
interactionAutocompleteInteractionThe raw interaction.
guildGuild | nullThe guild, if any.
memberGuildMember | nullThe member, if any.
userUserThe user typing.
focusedstringThe current value of the focused option.
optionNamestringThe focused option's name.

Reading the context from a component

useContext() from neocord returns the current interaction context from any component rendered by neocord. It throws when used elsewhere. The default return type is AnyContext, and you can name a narrower one.

This is useContext from neocord, not the one from react. React's still works for your own React contexts. See Custom components.

Checks before the handler

neocord runs these steps in order for commands, context menus, buttons, selects and modals:

  1. Resolve guild and member, and enforce guildOnly.
  2. Enforce permissions against interaction.memberPermissions. A missing permission gets an ephemeral list of what is missing.
  3. Start the autoDefer timer.
  4. Build the context. This resolves options.
  5. Run middleware, root to leaf.
  6. Parse the modal schema, for modals only. A failed parse replies with the issues and stops here.
  7. Apply cooldown. It is per user and route, kept in memory, so middleware denials and failed parses do not consume it.
  8. Send loading.tsx, for commands only.
  9. Run the handler and deliver what it returns.

A required option that cannot be resolved stops at step 4 with an ephemeral notice. A required member option whose user has left the server replies "The user given for "name" is not a member of this server."
