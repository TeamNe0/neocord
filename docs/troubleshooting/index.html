Most neocord errors say what to do. This page lists the common ones with their exact text, so you can search for what you see. If nothing here helps, include the output of neocord info in your report. It prints whether DISCORD_TOKEN is set, and never its value.

Invalid or missing token

Discord refused the login. Reset the token in the Developer Portal and update it. If you just reset it, the old value no longer works anywhere. The same problem has its own wording at two other points:

If there is no token at all, you see this:

Check that the variable is in a file the CLI loads. The order is .env, .env.<mode>, .env.local, .env.<mode>.local, and the real environment always wins. .env.local is skipped in test mode. See the CLI reference.

Environment validation failed

A variable in src/env.ts is missing or invalid, and the lines below this message name each one. Set it in the environment or a .env file. dev, start and a real deploy always validate. See Environment variables.

Disallowed intents (4014)

GuildMembers, GuildPresences and MessageContent are privileged. Enable each one you request in the Developer Portal, or remove it from intents in neocord.config.ts and from any defineFeature({ intents }). Intents from enabled features are merged into the config's list, so check both.

Other gateway close codes have their own messages:

Close codeMessage
4010Discord reported an invalid shard configuration (close code 4010). Check sharding.totalShards and sharding.shardList.
4011Discord requires this bot to shard (close code 4011). Run it with `neocord start` so the sharding manager is used.
4012Discord rejected the gateway API version (close code 4012). Update discord.js.
4013Discord reported invalid intents (close code 4013). Check the intents in neocord.config.ts: <intents>.

Discord does not let a bot reconnect after any of these, including a bot that was already running, for example when its token is reset. With no manager the bot logs the message, stops and exits with code 1. Under a manager, that shard stops and is not respawned, the other shards keep running, and the manager exits with code 1 once none are left. Fix the cause, then start the bot again.

A shard keeps respawning

A shard exited, and the manager is bringing it back with a growing delay, up to a minute. The lines around it say why, such as Could not reach Discord during a network outage, or an uncaught exception from your code. The delay resets once the shard has stayed ready for a minute. See Failure behaviour.

An event never fires

Events need intents. neocord test, neocord build and startup warn when one is missing:

messageCreate and messageUpdate also warn that message.content, embeds and attachments stay empty without the privileged MessageContent intent. See Events.

The three second limit

Discord gives each interaction three seconds to be acknowledged. neocord defers automatically after 2000 ms if your handler has not responded, so slow handlers do not hit the limit. You can change that in the config:

Auto defer can still miss the limit in these cases:

  • autoDefer: false is set and the handler is slow.
  • Something blocks the event loop, so the timer cannot fire. Synchronous file or process calls are the usual cause, and the no-blocking-calls rule catches them.
  • The process is overloaded, or the network is very slow. Lower after.

What an automatic defer does depends on the route. Commands get a deferred reply, which Discord shows as a thinking state. Buttons and selects get a deferred update, unless they set respond: "reply".

If a command returns nothing after an automatic defer, neocord removes the placeholder and logs:

Unknown interaction (10062)

The words after Could not change with the action, such as edit the reply, follow up or show the modal. Discord no longer accepts this interaction, usually because the three second limit passed before the first acknowledgement. See The three second limit. This is logged as a warning, and does not crash the handler.

Already acknowledged (40060)

Something else responded first. The likely causes are:

  • Two processes are using the same token. A common one is neocord dev running while production is up, or two replicas of a service. Each process receives the interaction and they race. Stop one.
  • A handler called ctx.interaction.reply directly. neocord follows the raw interaction's state, but it cannot see a response that is still in flight, so the two can race. Use ctx.reply or return JSX. The no-direct-interaction-reply rule catches this.

neocord recovers where it can. A first reply or update that fails this way is retried as an edit, and handlers do not crash. See Replying.

showModal fails

A modal must be the first response. Either loading.tsx applies to the route, the handler did slow work and autoDefer ran, or the handler already replied. Call ctx.showModal first. A modal submit cannot open another modal, and showModal is not on the modal context for that reason. See Modals.

A root loading.tsx breaks commands that open a modal

src/loading.tsx applies to every slash command and context menu command in the bot, because the closest loading file wins and the root is the fallback. neocord sends the loading reply before your handler runs, so the interaction is already acknowledged when the handler calls ctx.showModal. Buttons and selects ignore loading files, so a modal opened from a button is not affected.

Move the file into a feature or a command folder that contains no command that opens a modal. See Loading UI.

Nothing happened, or the warning about returning nothing

A command must return a node or call a reply method. Otherwise Discord shows that the application did not respond. Buttons and selects that return nothing are acknowledged with a deferred update, and modals acknowledge silently, so only commands get this warning. See Replying.

Commands not showing up

Work through these in order:

  1. Did you deploy? neocord dev only syncs to dev.guildId, and neocord build and neocord start do not deploy by default. Run neocord deploy. See Deploying commands.

  2. Is dev.guildId set? Without it, neocord dev warns:

    Set DEV_GUILD_ID to a server you own, and check that --no-deploy is not set.

  3. Does the hash say it is up to date? If you see already up to date, neocord skipped the request. If you think Discord has a different list, run neocord deploy --force.

  4. Are you looking at the right scope? neocord dev deploys to a guild, and neocord deploy deploys globally unless you pass --guild. If you registered the commands in one scope, they do not appear in the other.

  5. Was the bot invited with the applications.commands scope? See the quick start.

  6. Is the command hidden? permissions hide a command from members without them. guildOnly: true hides it in DMs. A feature with enabled: false contributes no commands.

  7. Does your Discord client have an old list? Reload the client with Ctrl+R, or Cmd+R on macOS.

If you see a command twice, it is registered both globally and in that server. See Development sync.

Interaction is no longer available

Users see this when no route matches a command or custom id, and the log says No route matches .... Usually you renamed or removed a route that an old message still uses, or the deployed commands are older than the running code. Deploy again if it is a command. See Upgrading.

This message has expired

The live session that owned this button or select is gone. Sessions are in memory per process, so they end on restart, and they also end after the idle timeout, live.ttl, which defaults to 14m, or when a new delivery replaces the message. See Live sessions.

TypeScript 7 and ESLint

tsc in a neocord project is native TypeScript 7, from the @typescript/native package. typescript-eslint needs the TypeScript 6 API, so the typescript package name is aliased to @typescript/typescript6:

This is Microsoft's documented side-by-side setup, and create-neocord writes it when you choose ESLint. Without ESLint, typescript is simply TypeScript 7. If @typescript-eslint/parser fails on the TypeScript API, or warns about an unsupported version, check that typescript resolves to the TypeScript 6 package and not to version 7.

Other tooling messages:

MessageFix
ESLint is not installed in this project.Run bun add -d eslint @teamneo/neocord-eslint-plugin. See ESLint.
Could not find tsc in this project.Run bun add -d typescript. neocord build --typecheck looks for @typescript/native first, then typescript.

The plugin supports flat config only, on ESLint 9 and 10. If path-based rules do nothing in a monorepo, set sourceDir relative to where ESLint runs. See ESLint.

A route has the wrong type

If route accepts any string, or rejects a route you just added, the generated types are out of date or not included:

  1. Run neocord typegen. neocord dev also regenerates them on change.
  2. Check that tsconfig.json includes .neocord/types.d.ts.

If ctx.app has no properties, the same fix applies, and you also need a src/context.ts. See How type safety works.

FAQ

Can I use embeds?

No. @teamneo/neocord-react renders Components V2 only, and every message it produces has the IsComponentsV2 flag. Discord does not allow embeds on those messages. Use Container, which has an accentColor, in place of an embed. See UI overview.

Can I use discord.js directly?

Yes. ctx.client and ctx.interaction are the real discord.js objects. Use them to read data and to call any API you need. Respond through ctx rather than ctx.interaction, so the reply state stays correct.

Why did @here not ping anyone?

allowedMentions defaults to { parse: [] } through the client options, so nothing is pinged unless you allow it. Use <Message allowedMentions={...}> for one message, or client.allowedMentions in the config for all of them.

Can anyone click my buttons?

Yes. Anyone who can see the message can click. Check ctx.user.id in the handler, or interaction.user.id in a live onClick, if that matters. A route can also use permissions, which is enforced at runtime on buttons and selects.

Can I respond to plain messages instead of slash commands?

Yes. Add events/messageCreate.ts with defineEvent, and enable GuildMessages and the privileged MessageContent intent. See Events.

Does a button still work after a restart?

A button with route or customId does, because the handler is found by its custom id. A button with onClick does not, because its handler lived in memory.

Do I need Bun?

No. Everything runs on Node too. neocord test is the one exception to check: it uses vitest if the project depends on it, and otherwise needs Bun, so on Node either install Bun or add vitest. See Testing.

Which Node version do I need?

@teamneo/neocord-cli declares Node 22.22 or later. neocord, @teamneo/neocord-react, @teamneo/neocord-routing, @teamneo/neocord-eslint-plugin and create-neocord declare Node 22.12 or later.

Why does ctx.guild have a type that includes null?

The handler may run in a DM. Set guildOnly: true on the route, and ctx.guild and ctx.member become non-null. The prefer-guild-only rule suggests this when it finds ctx.guild!.
