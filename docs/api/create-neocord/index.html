create-neocord

API reference for create-neocord: arguments, flags, exit behaviour and the generated project.

The scaffolder behind bun create neocord. It is a command only, and has no programmatic API. For a walkthrough, see the quick start.

You can also run the binary directly with bunx create-neocord my-bot.

Usage

Argument

ArgumentMeaning
[dir]The project directory, or . for the current directory. @scope/name creates name and keeps the scope in package.json. The default is my-neocord-bot.

The package name comes from the last part of the path, and must be a valid npm name. It must be lowercase, URL-safe, at most 214 characters, and must not start with a dot or underscore, contain any of ~ ' ! ( ) *, match a Node.js core module, or be node_modules or favicon.ico.

Flags

FlagValuesDefault without prompts
--db <orm>none, drizzle, prismanone
--dialect <dialect>sqlite, postgres, mysqlsqlite, when a database is chosen
--eslintAdd ESLint with the neocord rules.on
--no-eslintSkip ESLint.
--gitInitialize a git repository and make the first commit.on
--no-gitSkip git.
--installInstall dependencies.on
--no-installSkip installing dependencies.
--pm <manager>bun, npm, pnpm, yarnDetected from how the command was launched, otherwise bun
-y, --yesAccept defaults and never prompt.
--forceAllow a non-empty directory. Files with the same name are overwritten, and other files are kept.off
-h, --helpShow help.
-v, --versionPrint the version.

--db and --dialect reject values outside these lists. With npm, separate flags from the command with --:

Invalid combinations

InputResult
--dialect with --db none--dialect cannot be used with --db none.
--dialect without --db, and without prompts--dialect needs --db drizzle or --db prisma when running without prompts.
A non-empty directory without --force, and without prompts<dir> is not empty. Pass --force to scaffold into it anyway.
A path that exists and is a file<dir> exists and is not a directory.
An invalid package nameInvalid project name "<name>": <reason>

A directory that holds only a .git folder counts as empty.

Prompts

Prompts run when stdin and stdout are both terminals and --yes is not set. Without a terminal, or with --yes, nothing prompts and the defaults above apply. Any value given as a flag skips its prompt. The order is:

OrderPromptChoicesInitial value
1Where should the project be created?A pathmy-neocord-bot
2<dir> is not empty. Continue and overwrite files that have the same name?Yes or no, only for a non-empty directoryNo
3Which database toolkit do you want?None, Drizzle, Prisma. None is left out if --dialect was given.None, or Drizzle if --dialect was given
4Which database will you use?SQLite, PostgreSQL, MySQL, only if a database is chosenSQLite
5Add ESLint with the neocord rules?Yes or noYes
6Which package manager do you want to use?bun, npm, pnpm, yarnThe detected manager
7Initialize a git repository?Yes or noYes
8Install dependencies with <manager>?Yes or noYes

The package manager is detected from the npm_config_user_agent environment variable.

Exit codes

CodeWhen
0The project was created, even if git could not be initialized. Also after --help or --version, and when you cancel a prompt, which prints Cancelled. Nothing was created.
1Invalid flags or options, an unusable directory, or a failed dependency install. If the install fails, the project files stay in place and you can retry it yourself.

Git problems are warnings and do not change the exit code:

SituationBehaviour
The target is already inside a repositorySkips git init.
git is missing, or init failsWarns that it could not initialize git.
The first commit fails, usually because no git identity is setWarns that the files are staged but not committed.

The first commit's message is chore: initial commit.

What it generates

The base template writes these files:

Options

OptionAdds
ESLinteslint.config.js, a lint script, @teamneo/neocord-eslint-plugin, @typescript-eslint/parser and eslint. Also keeps @typescript/native next to the TypeScript 6 typescript alias.
No ESLinttypescript is TypeScript 7 directly.
Bun as package manager@types/bun, and "types": ["node", "bun"] in tsconfig.json.
Drizzledrizzle.config.ts, src/db/index.ts, src/db/schema.ts, src/context.ts, an .env.example and src/env.ts with DATABASE_URL, and a /remember command.
Prismaprisma.config.ts, prisma/schema.prisma, src/db/index.ts, src/context.ts, an .env.example and src/env.ts with DATABASE_URL, a /remember command, a postinstall script and a db:generate step in the Dockerfile.

See Drizzle and Prisma for what each dialect adds.

NEOCORD_TEMPLATE_VERSION_OVERRIDES

Set this environment variable to a JSON object to replace any of the versions above. It is useful for testing against local packages.

Invalid JSON, a value that is not an object, or a non-string version makes the command fail with a message that names the variable.
