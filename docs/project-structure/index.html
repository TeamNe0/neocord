Project structure

Every file and folder convention in a neocord project, and what each one does.

  • The full tree
  • Root files
  • Feature folders
  • Route folders
  • Special folder names
  • Segment files
  • Test files
  • The generated .neocord folder
  • Changing the folders

neocord decides what a file is from its path. This page lists every convention. classifyFile in @teamneo/neocord-routing is the source of truth, and the CLI, the runtime and the ESLint plugin all use it, so a file means the same thing to each of them.

The full tree

Files can end in .ts or .tsx. Files with other extensions in the features folder are ignored, and so are .d.ts files, folders that start with ., and node_modules.

Root files

FileExportPurpose
neocord.config.tsdefineConfig({ ... })Bot configuration. .mts, .js and .mjs also work. The CLI finds the project root by looking for this file in the current folder and its parents.
src/env.tsAnythingEnvironment validation, usually with T3 Env. Not routed. See Environment variables.
src/context.tsdefineContext(...)Shared services, read through ctx.app. See App context.
src/middleware.tsdefineMiddleware(...)Applies to every interaction. See Middleware.
src/layout.tsxA componentWraps nodes that handlers return or send. See Layouts.
src/error.tsxA componentShown when a handler throws. See Error boundaries.
src/loading.tsxA componentSent first for commands. See Loading UI.

Other files directly in src, and folders such as src/lib, are outside the router. Import them as normal.

Feature folders

Each folder in src/features is a feature. Only these things can sit directly in a feature folder. Anything else is an error that tells you to use a private folder.

EntryPurpose
feature.tsOptional defineFeature. See Features.
middleware, layout, error, loadingSegment files for this feature.
commands, user-commands, message-commandsCommands.
buttons, selects, modalsInteraction routes.
events, tasksBackground work.
Folders and files starting with _Private code, at any depth.

Route folders

FolderFile nameHelperRoute idNotes
commandscommanddefineCommandban, mod warnThe feature is not part of the name. At most three levels. See Slash commands.
commandsgroupdefineGroupMetadata for a parent of subcommands.
user-commandscommanddefineUserCommandmoderation/reportSee Context menus.
message-commandscommanddefineMessageCommandmoderation/quoteSee Context menus.
buttonsbuttondefineButtonmoderation/confirm-ban/[userId]See Buttons.
selectsselectdefineSelectmoderation/pick-roleSee Selects.
modalsmodaldefineModalmoderation/ban-reason/[userId]See Modals.
eventsAnydefineEventguildMemberAddThe name comes from the file or its folder. See Events.
tasksAnydefineTaskmoderation/cleanupThe name comes from the file or its folder. See Tasks.

Files in commands, buttons, selects and the others must use the exact file name, in a named folder. So commands/ping.tsx and commands/ban/helper.ts are errors. Move helpers into a folder starting with _.

Special folder names

NameMeaningExample
(group)Organises files without changing the route. It still counts as a scope for segment files.commands/(staff)/mod/warn/command.tsx is /mod warn.
[param]One dynamic segment.buttons/confirm/[userId]/button.tsx
[...rest]Catches the remainder. Must be last.buttons/page/[...rest]/button.tsx
_privateNever routed._lib/format.ts, _components/Stat.tsx

See Dynamic routes for how params work.

Segment files

middleware, layout, error and loading files apply to everything beneath them. They can live in src, in a feature folder, in a route kind folder such as commands, or in any folder under it. Only one of each is allowed per folder.

KindHow the chain works
middlewareAll of them run, from root to leaf.
layoutAll of them wrap the node, with the root outermost.
errorThe closest one wins.
loadingThe closest one wins. Commands only.

/Warning

Segment file names do not work inside events and tasks, because every file there is a route. events/error.ts listens to the discord.js error event.

Test files

Files ending in .test.ts, .test.tsx, .spec.ts or .spec.tsx are ignored by the router, so they can sit next to the file they test. See Testing.

The generated .neocord folder

The CLI writes generated code to .neocord. Add it to .gitignore. The CLI reference lists every file in it.
