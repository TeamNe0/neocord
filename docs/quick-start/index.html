Getting started/

Quick start with the CLI

Scaffold a bot with create-neocord, get a token from the Discord Developer Portal, invite the bot and run /ping.

create-neocord writes a working bot for you, with a /ping command, an /about command with a button, environment validation and a production Dockerfile. This page goes from nothing to seeing /ping answer in your own server.

Requirements

  • Bun, or Node. neocord, @teamneo/neocord-react and create-neocord declare Node 22.12 or later, and @teamneo/neocord-cli declares Node 22.22 or later, so use Node 22.22 or later if you run the CLI on Node.
  • A Discord account, and a server where you can add bots. You can create an empty server for this.

Running without prompts

Without a TTY, or with --yes, create-neocord never prompts. It exits with code 1 and a message when:

  • A value is invalid, such as a project name with uppercase letters.
  • The directory is not empty and --force is missing.
  • --dialect is combined with --db none, or --dialect is given with no --db.
  • Installing dependencies fails. The project files stay in place, so you can retry the install yourself.

If this directory is already inside a git repository, git init is skipped. If git cannot make the first commit, for example because no identity is set, the files are staged and you see a warning.

What the options change

  • --db adds src/db, a src/context.ts that exposes the client as ctx.app.db, DATABASE_URL in src/env.ts and .env.example, a /remember command, and the db:push, db:generate, db:migrate and db:studio scripts. Prisma also gets db:deploy. See Drizzle and Prisma.
  • --eslint adds eslint.config.js, the lint script, and native TypeScript 7 next to TypeScript 6. Without it, typescript is TypeScript 7 alone. Manual setup explains why.
  • Choosing bun as the package manager adds @types/bun and sets "types": ["node", "bun"] in tsconfig.json.

Create the Discord application

  1. Open the Discord Developer Portal and select New Application. Give it a name.
  2. On General Information, copy the Application ID. You only need it to build the invite link below. neocord reads the application from the token when it deploys commands, so it never goes in your config.
  3. Open Bot and select Reset Token. Copy the token straight away, because Discord only shows it once. Treat it like a password.

Leave Privileged Gateway Intents off for now. The generated config only asks for Guilds, which is not privileged.

Invite the bot

Open this URL with your Application ID filled in, and choose your server:

The same link can be built in the portal under OAuth2, then URL Generator. Select the bot and applications.commands scopes. Add bot permissions there if your commands need them.

Set the environment

Copy .env.example to .env:

To get your server id, turn on Developer Mode in Discord under User Settings, then Advanced. Right-click your server and select Copy Server ID.

DEV_GUILD_ID matters during development. neocord dev syncs commands to that one server, so they appear immediately. Without it, the CLI prints "No dev.guildId set, so commands are not synced in development." and your commands will not show up.

/Warning

The generated .gitignore ignores .env* except .env.example. Never commit a token. The ESLint rule no-hardcoded-token catches tokens written into source files.
