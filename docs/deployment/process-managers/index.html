neocord manages its own shards, including respawning them after a crash with a growing delay, but it does not restart itself if the manager process exits or the machine reboots. Use a process manager for that.

What neocord does on a signal

The CLI forwards SIGINT, SIGTERM and SIGHUP to the process it launched. Under neocord start, that process is the sharding manager.

When the manager receives SIGINT, SIGTERM or SIGHUP:

  1. It logs Received <signal>, stopping shards. and cancels pending respawns.
  2. It asks each shard to shut down, and waits up to twelve seconds for each one.
  3. It kills any shard still running, then exits with code 0.

Each shard shuts down in this order:

  1. Stop taking new interactions and events.
  2. Wait for running tasks and running handlers, up to five seconds. These run at the same time, so a slow handler gets to acknowledge its click and still has a working ctx.app.
  3. Expire live sessions, spending up to two seconds on the final edits that disable their components.
  4. Call the dispose function from src/context.ts.
  5. Destroy the Discord client, log Stopped. and exit with code 0.

That is seven seconds before dispose, and the manager's limit leaves about five more for dispose and the client. A shard killed at the twelve second limit does not finish these steps, so keep dispose short. Set your process manager's stop timeout above twelve seconds, as the examples below do.

A second SIGTERM or SIGHUP during shutdown is ignored, so a parent repeating its signal does not interrupt dispose. A second SIGINT at least one second after the first makes a shard exit at once with code 130, so pressing Ctrl+C again still works when something is stuck.

A process that started neocord with an IPC channel can also send the message { neocord: "shutdown" }. startBot and startManager treat it like SIGTERM, and ignore every other message. This is how neocord dev stops the bot on Windows, where child.kill("SIGTERM") ends a process immediately.

Exit codes and restart loops

neocord start exits with the manager's exit code.

Exit codeMeaning
0A requested stop finished.
1Startup failed, after logging one error with no stack trace. Or the bot was running and no shards are left to run. See Failure behaviour.

/Warning

A bad token does not loop inside neocord: a shard that reports one is not respawned. A process manager that restarts the whole command undoes that protection. Always set a restart delay and a limit, as in the examples below.

pm2

Run the bot with one instance in fork mode. Do not use cluster mode or more than one instance, because each copy would start its own manager and connect the same shards. The file must end in .cjs because a neocord project sets "type": "module".

Windows

Windows has no POSIX signals. Pressing Ctrl+C in a console sends the event to the whole console, so the CLI waits up to twenty seconds for the child to stop by itself before it forwards SIGINT. Other ways of ending the process may skip the shutdown steps above.

Logs

neocord writes debug and info to stdout, and warn and error to stderr, with an ISO timestamp on each line. Tokens are redacted. It does not write log files, so use your process manager's log handling. Set the level with logLevel in the config or NEOCORD_LOG_LEVEL in the environment, which takes priority. The levels are debug, info, warn, error and silent.
