This page builds the same project as create-neocord, one file at a time. Every file is shown in full, so you can follow this page on its own and finish with a working bot.

You need Bun or Node. neocord and @teamneo/neocord-react declare Node 22.12 or later, and @teamneo/neocord-cli declares Node 22.22 or later, so use Node 22.22 or later if you run the CLI on Node.

Create the folder

package.json

Create package.json with these scripts and dependencies:

PackageWhy it is here
neocordThe define* helpers and the bot runtime.
@teamneo/neocord-reactThe JSX components and renderer.
discord.js, reactPeer dependencies. neocord needs discord.js 14.28 or later and React 19.3 or later.
@t3-oss/env-core, zodEnvironment validation in src/env.ts.
@teamneo/neocord-cliThe neocord binary.
@teamneo/neocord-eslint-plugin, eslint, @typescript-eslint/parserLinting.
@types/node, @types/reactTypes for Node and React.
@typescript/native, typescriptThe type checker. See the next section.

If you use Bun, also add "@types/bun": "latest" to devDependencies.

TypeScript 7 and TypeScript 6

The two TypeScript entries are aliases, and both are deliberate:

  • @typescript/native installs TypeScript 7, the native compiler. It provides the tsc command, so tsc --noEmit and neocord build --typecheck use it.
  • typescript installs TypeScript 6 under the name typescript, because typescript-eslint needs the TypeScript 6 API and imports the package called typescript.

This is Microsoft's documented side-by-side setup. If you do not use ESLint, you need only one entry: remove @typescript/native and set "typescript": "npm:typescript@^7.0.2". You can then also remove @teamneo/neocord-eslint-plugin, @typescript-eslint/parser, eslint and the lint script, which is what create-neocord --no-eslint does.

Install

tsconfig.json

If you use Bun, set "types": ["node", "bun"].

The last entry in include matters. .neocord/types.d.ts is generated by the CLI, and it is what makes route props and ctx.app typed. The bundler reads this file too, so the ~/* path alias works at runtime. See How type safety works.

.gitignore

.neocord holds generated code and is safe to delete. Everything in .env* is ignored except the example file.

Environment files

Create an example file that is safe to commit:

Then create your real one. To fill it in:

  1. Open the Discord Developer Portal, select New Application and name it.
  2. Copy the Application ID from General Information. You need it for the invite link.
  3. Open Bot, select Reset Token and copy the token.
  4. In Discord, turn on Developer Mode under User Settings, then Advanced. Right-click your server and select Copy Server ID.

Invite the bot to that server by opening this URL with your Application ID filled in:

The CLI loads .env, .env.<mode>, .env.local and .env.<mode>.local in that order. Later files override earlier ones, and real environment variables always win. See the CLI reference.

Run it

neocord dev syncs your commands to DEV_GUILD_ID and starts the bot. Type /ping in your server:

If nothing shows up, see Troubleshooting.

Test

neocord test validates every route and command payload, then runs your tests. It needs Bun on the machine, or vitest in your dependencies. Otherwise it stops with "No test runner found."

Build and start

For production, build the bundle, register your commands globally, and start the sharding manager:

StepWhat it does
neocord buildWrites shard.js, manager.js and deploy.js to .neocord/build.
neocord deployRegisters commands with Discord, and skips the call when nothing changed.
neocord startLaunches the manager, which starts the shards.

neocord start validates the environment, so DISCORD_TOKEN must be set. Global commands can take time to appear in Discord clients. See Deploying commands and the Production checklist.
