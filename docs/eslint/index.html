ESLint

Set up @teamneo/neocord-eslint-plugin, choose a config, and see what every rule checks.

@teamneo/neocord-eslint-plugin checks what each routed file has to export, catches Discord limits before you deploy, and gives best practice advice. All rules read the AST only, so they need no type information and work with any parser. The plugin supports flat config only, on ESLint 9 and 10.

Setup

A project scaffolded with --eslint already has this. To add it by hand, install the packages:

Then create the config. The plugin's configs do not set a parser, so add @typescript-eslint/parser yourself:

Run it with neocord lint:

If you use TypeScript 7, typescript must be aliased to TypeScript 6 because @typescript-eslint/parser needs the TypeScript 6 API. Manual setup explains the alias, and Troubleshooting covers the errors you see without it.

Configs

ConfigBehaviour
neocord.configs.recommendedFile contracts and correctness rules are errors, advice rules are warnings, and require-error-boundary is off.
neocord.configs.strictEvery rule is an error, including require-error-boundary.

Both configs register the plugin under the neocord namespace, so rule ids look like neocord/no-process-env. To change one rule, add it after the config:

Settings

Paths are computed from the directory ESLint runs in. If your source lives elsewhere, set the same values you use in defineConfig:

SettingDefaultMeaning
sourceDir"src"Source folder, relative to the ESLint working directory.
featuresDir"<sourceDir>/features"Features folder, relative to the ESLint working directory.

/Warning

In a monorepo where ESLint runs from the repository root, include the project folder, such as sourceDir: "apps/bot/src". Otherwise files are treated as outside the project and the path-based rules do nothing.

Rules

The severity column shows recommended and then strict. "Fix" means eslint --fix can correct it, and "Suggestion" means your editor offers a change.

File contracts

RuleSeverityFixesDescription
require-default-exporterror / errorRoute, group, feature, context and middleware files need a default export. Layout, error and loading files must default-export a function component.
require-define-helpererror / errorThe default export must be a call to the matching helper, such as defineCommand in commands and defineUserCommand in user-commands.
route-matches-patherror / errorFix, SuggestionThe first argument of defineButton, defineSelect, defineModal and defineEvent must be a literal equal to the id from the path.
no-extra-exportserror / errorRouted files export only the default. Type exports are fine.
no-unknown-route-fileerror / errorReports files in the features folder that neocord cannot classify, and why.
valid-command-nameerror / errorFolders under commands must be valid lowercase Discord names, at most three levels deep.
no-command-with-subcommandserror / errorA folder with a command file cannot also hold nested commands.
require-group-filewarn / errorNested commands need a group.ts in their root command folder, for the description.
valid-event-nameerror / errorSuggestiondefineEvent must name a real discord.js client event, and the closest name is suggested.
valid-command-definitionerror / errorChecks required properties, description lengths, option names, option descriptions and the option count.
valid-modal-definitionerror / errordefineModal needs a literal or function title of at most 45 characters, plus render and submit.

UI

RuleSeverityFixesDescription
no-embed-builderswarn / errorForbids discord.js builders and raw embeds or components in send calls. Use @teamneo/neocord-react.
valid-component-nestingerror / errorChecks the static JSX structure of @teamneo/neocord-react components, including aliased imports. Custom components and expressions are skipped.
prefer-route-propwarn / errorRecommends route over a literal customId on buttons and selects. Modal fields are exempt.
no-text-in-action-rowerror / errorForbids text directly inside ActionRow, MediaGallery and selects.

Best practices

RuleSeverityFixesDescription
no-direct-interaction-replywarn / errorForbids ctx.interaction.reply and friends. Use ctx.reply or return JSX.
no-client-instantiationerror / errorForbids creating a discord.js Client or ShardingManager, or calling .login() on a client, in project source.
no-process-envwarn / errorForbids process.env outside src/env.ts and root *.config.* files.
no-hardcoded-tokenerror / errorForbids strings shaped like Discord tokens.
no-blocking-callswarn / errorForbids *Sync calls from fs and child_process, and Atomics.wait, in route files.
prefer-guild-onlywarn / errorSuggestionRecommends guildOnly: true over ctx.guild! and ctx.member!.
no-unawaited-context-callswarn / errorSuggestionRequires ctx.reply and similar calls to be awaited, returned or voided.
require-error-boundaryoff / errorEach feature should have its own error.tsx. It is reported once per feature, on feature.ts or the feature's first file.
no-mass-mentionswarn / errorForbids everyone in a literal allowedMentions.parse, and literal @everyone or @here in JSX text.

Rules that scan the project

no-command-with-subcommands, require-group-file and require-error-boundary read the features folder from disk, so they can compare a file with its siblings. The scan is cached for two seconds, and skips node_modules and folders that start with . or _. A file that does not exist on disk is not compared.
