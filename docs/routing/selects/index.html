Selects

Handle string, user, role, channel and mentionable selects with defineSelect.

Selects work like buttons. You send a select component with a route, and a select.tsx file handles what the user picked. There are five kinds, and type on the handler must match the component.

A string select

Picking an option runs select.tsx, and what it returns updates the same message:

defineSelect

FieldTypeRequiredMeaning
execute(ctx) => node | voidYesThe handler. May be async.
type"string" | "user" | "role" | "channel" | "mentionable"NoThe select kind. Defaults to "string".
respond"update" | "reply"NoWhat a returned node does. Defaults to "update".
permissionsPermissionsString[]NoChecked at runtime.
guildOnlybooleanNoRejects use outside a server. Makes ctx.guild and ctx.member non-null.
ephemeralbooleanNoReplies from this handler are ephemeral by default.
cooldownDurationNoPer user and route.
layoutbooleanNofalse skips layouts.

The select context

Everything in the handler context, plus params, message, update and deferUpdate as on buttons, and:

FieldAvailable when type isType
valuesEvery typestring[]
usersuser, mentionableCollection<string, User>
membersuser, mentionableCollection of members
rolesrole, mentionableCollection of roles
channelschannelCollection of channels

For selects other than string, values holds the ids of what was picked. type narrows the context, so ctx.roles is only available when type is "role" or "mentionable".

Types and components

typeComponentPicks
"string"StringSelectYour Option values
"user"UserSelectUsers
"role"RoleSelectRoles
"channel"ChannelSelectChannels
"mentionable"MentionableSelectUsers and roles

If the two do not match, the interaction does not reach your handler. neocord logs a warning naming the file, and the user gets the ephemeral notice "This interaction is no longer available."

Params

Select routes can have params, like every interaction route:

update or reply

Like buttons, a returned node updates the message unless respond: "reply" is set, and a handler that returns nothing without acknowledging gets a deferUpdate. See Replying.

Other ways to address a select

Selects take route and params, a raw customId, or onSelect for a live session. The types keep them mutually exclusive. See Interactive components for every prop and limit.

Selects can also go inside a modal, where they are part of the form and use a customId. See Modal components.
