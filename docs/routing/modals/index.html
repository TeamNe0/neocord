Modals

Define modals with defineModal, parse submissions with a schema and read typed values.

A modal is a modal.tsx file that defines both the form and what happens when it is submitted. Open it from another handler with ctx.showModal.

A modal

Open it from a button, a command or a context menu:

defineModal

FieldTypeRequiredMeaning
titlestring or (ctx) => stringYes1-45 characters.
render(ctx) => nodeYesThe form.
submit(ctx) => node | voidYesRuns when the form is submitted. May be async.
schemaStandard SchemaNoParses the values.
respond"reply" (default) or "update"NoWhat a node returned from submit does. See After submit.
permissionsPermissionsString[]NoChecked at runtime when the form is submitted.
guildOnlybooleanNoMakes ctx.guild and ctx.member non-null in submit.
ephemeralbooleanNoReplies from submit are ephemeral by default.
cooldownDurationNoPer user and route, applied to submissions.
layoutbooleanNofalse skips layouts for what submit returns.

render and title

render and a function title both receive the same object:

FieldTypeMeaning
paramsFrom the routeThe params given to showModal.
field(name)stringReturns the field's custom id. With a schema, it only accepts the schema's keys, so a typo is a compile error.

render is synchronous, and a suspending component throws. Layouts do not apply to modals. A modal holds 1-5 Label or TextDisplay children, and each Label wraps one control. Text can sit directly in the form, and a fragment can return several children. See Modal components for every control.

showModal

ctx.showModal(route, params) is available on commands, context menus, buttons and selects. Modal submit, autocomplete, events and tasks do not have it.

  • route is typed from your modal files, and params is required exactly when the route has params.
  • It must be the first response. If the interaction has already been acknowledged, it throws an error that says so.
  • A loading.tsx that applies to the route sends a reply first, so showModal cannot follow it.
  • A modal cannot open from a modal submit.

Values without a schema

ctx.values is Record<string, string | string[] | boolean>, keyed by each control's customId:

ControlValue
TextInputstring. Omitted when left blank.
Selects, CheckboxGroupstring[]
FileUploadstring[] of attachment ids.
RadioGroupstring. Omitted when nothing is chosen.
Checkboxboolean

Read uploaded files with ctx.fields.getUploadedFiles(name).

Schemas

schema is any Standard Schema, such as zod, valibot or arktype. neocord has no dependency on any of them. ctx.values becomes the schema's output type:

The schema runs after middleware, so a user that middleware blocks never reaches async refine logic, and ctx.values is not available to middleware. It runs before cooldown, so a failed parse does not use up the cooldown.

TextInput values are omitted when left blank, so use .optional() for a field the user can skip. If parsing fails, submit does not run, and the user gets an ephemeral message with the issues:

The exact wording of each issue comes from your schema library.

The modal context

Everything in the handler context except showModal, plus:

FieldTypeMeaning
paramsFrom the routeThe params from the custom id.
valuesFrom the schemaThe parsed values. Set after middleware, so only submit can read them.
fieldsModalSubmitFieldsThe discord.js fields, for uploaded files and raw access.
update(node, options?)Promise<void>Updates the message the modal was opened from.
deferUpdate()Promise<void>Acknowledges without changing that message.

A modal cannot open another modal, which is why showModal is missing.

After submit

submit doesResult
Returns a nodectx.reply(node). With respond: "update", ctx.update(node).
Calls ctx.reply, ctx.update or similarThat response stands.
Nothing, on a modal opened from a message componentneocord defers the update.
Nothing, on a modal opened from a commandneocord acknowledges silently, by deferring ephemerally and deleting the reply.

Updating the message the modal came from

When a button opens a modal, respond: "update" makes the submission change the message that button is on instead of sending a new one. This suits a confirmation flow, where the buttons should disappear once the form is sent.

A modal opened from a slash command has no message to update. There, respond: "update" and ctx.update send a reply, and ctx.deferUpdate defers one.

See Replying.
