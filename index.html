Your file tree is your Discord bot.

Put a file in commands/ping and you have /ping. Return JSX from the handler and neocord renders it as a Discord message. Built on discord.js and React, for Bun and Node.

@teamneo/neocord-react is a real React renderer. Options infer their types, and Discord's limits are checked when the message renders, with errors that name the component.

Messages your bot can send

Each preview is drawn to match Discord, and links to the page that explains how to build it.

  • #general

    Live state
    Put onClick on a button and useState keeps working between clicks. These two buttons run the same logic.

  • #general

    Modals
    A modal.tsx file holds the form and its submit handler, with a schema for the values.

  • #general

    Selects
    Send a select with a route, and a select.tsx file handles what the user picked.

  • #general

    Attachments
    Pass a Buffer to File or MediaItem, and neocord attaches the bytes to the message for you.

  • #general

    Slow handlers
    Handlers that near Discord's three second limit are deferred for you, and the reply fills this in.

  • #general

    Error views
    When a handler throws, the closest error.tsx decides what the user sees.

What else you get

  • /Type-checked routes
    The CLI generates types from your files, so a typo in a button's route is a compile error and params are required exactly when a route has them.
  • /Replies that do not race
    One state machine owns every interaction. Slow handlers are deferred before Discord's three second limit, and reply, edit and follow-up choose themselves.
  • /Stateful messages
    Put onClick on a button and useState works, with an idle timeout that disables the components when the session ends.
  • /Sharding on Bun and Node
    neocord start launches the sharding manager, in process or worker mode, and a bad token stops respawning instead of looping against Discord.
  • /Tests without a gateway
    neocord/testing runs the real dispatch pipeline on fake interactions, and neocord test validates every route and command payload first.
  • /Lint rules for the conventions
    24 ESLint rules check file contracts, component nesting and Discord limits, with autofixes for route ids.
