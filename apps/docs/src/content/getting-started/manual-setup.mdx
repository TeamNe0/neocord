This page builds the same project as [`create-neocord`](/docs/quick-start), one file at a time. Every file is shown in full, so you can follow this page on its own and finish with a working bot.

You need [Bun](https://bun.com/docs/installation) or Node. `neocord` and `@neocord/react` declare Node 22.12 or later, and `@neocord/cli` declares Node 22.22 or later, so use Node 22.22 or later if you run the CLI on Node.

## Create the folder

```sh
mkdir my-bot
cd my-bot
```

## package.json

Create `package.json` with these scripts and dependencies:

```json title="package.json"
{
  "name": "my-bot",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "neocord dev",
    "build": "neocord build",
    "start": "neocord start",
    "deploy": "neocord deploy",
    "test": "neocord test",
    "typecheck": "neocord typegen && tsc --noEmit",
    "lint": "neocord lint"
  },
  "dependencies": {
    "@neocord/react": "^0.1.0",
    "@t3-oss/env-core": "^0.13.11",
    "discord.js": "^14.28.1",
    "neocord": "^0.1.0",
    "react": "^19.3.1",
    "zod": "^4.6.7"
  },
  "devDependencies": {
    "@neocord/cli": "^0.1.0",
    "@neocord/eslint-plugin": "^0.1.0",
    "@types/node": "^26.6.6",
    "@types/react": "^19.3.0",
    "@typescript-eslint/parser": "^8.72.1",
    "@typescript/native": "npm:typescript@^7.0.2",
    "eslint": "^10.14.0",
    "typescript": "npm:@typescript/typescript6@^6.0.2"
  },
  "engines": {
    "node": ">=22.22.0"
  }
}
```

| Package | Why it is here |
| --- | --- |
| `neocord` | The `define*` helpers and the bot runtime. |
| `@neocord/react` | The JSX components and renderer. |
| `discord.js`, `react` | Peer dependencies. neocord needs discord.js 14.28 or later and React 19.3 or later. |
| `@t3-oss/env-core`, `zod` | Environment validation in `src/env.ts`. |
| `@neocord/cli` | The `neocord` binary. |
| `@neocord/eslint-plugin`, `eslint`, `@typescript-eslint/parser` | Linting. |
| `@types/node`, `@types/react` | Types for Node and React. |
| `@typescript/native`, `typescript` | The type checker. See the next section. |

If you use Bun, also add `"@types/bun": "latest"` to `devDependencies`.

## TypeScript 7 and TypeScript 6

The two TypeScript entries are aliases, and both are deliberate:

```json
"@typescript/native": "npm:typescript@^7.0.2",
"typescript": "npm:@typescript/typescript6@^6.0.2"
```

- `@typescript/native` installs TypeScript 7, the native compiler. It provides the `tsc` command, so `tsc --noEmit` and `neocord build --typecheck` use it.
- `typescript` installs TypeScript 6 under the name `typescript`, because typescript-eslint needs the TypeScript 6 API and imports the package called `typescript`.

This is Microsoft's documented side-by-side setup. If you do not use ESLint, you need only one entry: remove `@typescript/native` and set `"typescript": "npm:typescript@^7.0.2"`. You can then also remove `@neocord/eslint-plugin`, `@typescript-eslint/parser`, `eslint` and the `lint` script, which is what `create-neocord --no-eslint` does.

## tsconfig.json

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2023",
    "lib": ["ES2023"],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "skipLibCheck": true,
    "types": ["node"],
    "paths": {
      "~/*": ["./src/*"]
    }
  },
  "include": ["src", "neocord.config.ts", ".neocord/types.d.ts"]
}
```

If you use Bun, set `"types": ["node", "bun"]`.

The last entry in `include` matters. `.neocord/types.d.ts` is generated by the CLI, and it is what makes `route` props and `ctx.app` typed. The bundler reads this file too, so the `~/*` path alias works at runtime. See [How type safety works](/docs/type-safety).

## Environment files

Create an example file that is safe to commit:

```text title=".env.example"
DISCORD_TOKEN=
DEV_GUILD_ID=
```

Then create your real one. To fill it in:

1. Open the [Discord Developer Portal](https://discord.com/developers/applications), select **New Application** and name it.
2. Copy the **Application ID** from **General Information**. You need it for the invite link.
3. Open **Bot**, select **Reset Token** and copy the token.
4. In Discord, turn on **Developer Mode** under **User Settings**, then **Advanced**. Right-click your server and select **Copy Server ID**.

```text title=".env"
DISCORD_TOKEN=your-bot-token
DEV_GUILD_ID=your-server-id
```

Invite the bot to that server by opening this URL with your Application ID filled in:

```text
https://discord.com/oauth2/authorize?client_id=YOUR_APPLICATION_ID&scope=bot+applications.commands
```

The CLI loads `.env`, `.env.<mode>`, `.env.local` and `.env.<mode>.local` in that order. Later files override earlier ones, and real environment variables always win. See the [CLI reference](/docs/cli).

## src/env.ts

This file validates the environment, so a missing token is a readable error at startup:

```ts title="src/env.ts"
import { createEnv } from "@t3-oss/env-core";
import { z } from "zod";

export const env = createEnv({
  server: {
    DISCORD_TOKEN: z.string().min(1),
    DEV_GUILD_ID: z.string().min(1).optional(),
    NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  },
  runtimeEnv: process.env,
  emptyStringAsUndefined: true,
  skipValidation: process.env.SKIP_ENV_VALIDATION === "true",
});
```

`skipValidation` lets commands such as `neocord typegen` and `neocord build` work with no secrets. See [Environment variables](/docs/type-safety/environment).

## neocord.config.ts

```ts title="neocord.config.ts"
import { defineConfig } from "neocord";
import { env } from "./src/env";

export default defineConfig({
  intents: ["Guilds"],
  token: env.DISCORD_TOKEN,
  dev: { guildId: env.DEV_GUILD_ID, shards: 1 },
});
```

| Field | Meaning |
| --- | --- |
| `intents` | Gateway intents, as keys of `GatewayIntentBits`. `Guilds` is not privileged. |
| `token` | The bot token. Without it, neocord reads `process.env.DISCORD_TOKEN`. |
| `dev.guildId` | The server `neocord dev` syncs commands to. |
| `dev.shards` | The shard count in development. |

## The first command

A folder under `commands` in a feature is a slash command. This file is `/ping`:

```tsx title="src/features/general/commands/ping/command.tsx"
import { Message } from "@neocord/react";
import { defineCommand, option } from "neocord";

export default defineCommand({
  description: "Check that the bot is responding",
  options: {
    message: option.string({ description: "Text to send back", maxLength: 100 }),
  },
  execute(ctx) {
    return <Message>Pong! {ctx.options.message ?? `Gateway latency is ${ctx.client.ws.ping} ms.`}</Message>;
  },
});
```

The feature is `general`, which is not part of the command name, because slash commands are global. `ctx.options.message` is `string | undefined`, because the option is not required.

## A shared component

Folders that start with `_` are private and never become routes, so they are the place for shared code:

```tsx title="src/features/general/_components/Stat.tsx"
import { Bold, TextDisplay } from "@neocord/react";

export interface StatProps {
  label: string;
  value: string | number;
}

export function Stat({ label, value }: StatProps) {
  return (
    <TextDisplay>
      <Bold>{label}:</Bold> {value}
    </TextDisplay>
  );
}
```

## The first button

This command shows a message with a button. The button's `route` is the id of the handler file:

```tsx title="src/features/general/commands/about/command.tsx"
import { ActionRow, Button, Container, Heading } from "@neocord/react";
import { defineCommand } from "neocord";
import { Stat } from "../../_components/Stat";

export default defineCommand({
  description: "Show information about this bot",
  execute(ctx) {
    return (
      <Container accentColor="#5865f2">
        <Heading>About {ctx.client.user.username}</Heading>
        <Stat label="Servers" value={ctx.client.guilds.cache.size} />
        <Stat label="Latency" value={`${ctx.client.ws.ping} ms`} />
        <ActionRow>
          <Button route="general/refresh" style="secondary">
            Refresh
          </Button>
        </ActionRow>
      </Container>
    );
  },
});
```

This file handles the click. A button's route id is `<feature>/<path>`, so the first argument is `general/refresh`, and the node it returns updates the message:

```tsx title="src/features/general/buttons/refresh/button.tsx"
import { ActionRow, Button, Container, Heading } from "@neocord/react";
import { defineButton } from "neocord";
import { Stat } from "../../_components/Stat";

export default defineButton("general/refresh", {
  execute(ctx) {
    return (
      <Container accentColor="#5865f2">
        <Heading>About {ctx.client.user.username}</Heading>
        <Stat label="Servers" value={ctx.client.guilds.cache.size} />
        <Stat label="Latency" value={`${ctx.client.ws.ping} ms`} />
        <ActionRow>
          <Button route="general/refresh" style="secondary">
            Refresh
          </Button>
        </ActionRow>
      </Container>
    );
  },
});
```

## An error view and an event

These are optional, but the scaffolder adds them and they show two more conventions.

`src/error.tsx` is shown ephemerally when a handler under it throws:

```tsx title="src/error.tsx"
import { Container, Heading, Subtext } from "@neocord/react";

export default function ErrorView() {
  return (
    <Container accentColor="#ed4245">
      <Heading>Something went wrong</Heading>
      <Subtext>The error was logged. Please try again in a moment.</Subtext>
    </Container>
  );
}
```

A file named after a client event listens to it:

```ts title="src/features/general/events/clientReady.ts"
import { defineEvent } from "neocord";

export default defineEvent("clientReady", {
  once: true,
  execute(ctx, client) {
    ctx.logger.info(`Logged in as ${client.user.tag}`);
  },
});
```

## A test

Tests run on `bun test`, or on vitest if it is a project dependency. Test files next to routes are ignored by the router:

```tsx title="src/features/general/commands/ping/command.test.tsx"
import assert from "node:assert/strict";
import { test } from "node:test";
import { runCommand } from "neocord/testing";
import command from "./command";

test("ping replies with the text it was given", async () => {
  const { replies } = await runCommand(command, { options: { message: "hello" } });

  assert.equal(replies.length, 1);
  assert.match(JSON.stringify(replies[0]), /hello/);
});
```

This test is written for `bun test`. vitest does not collect `node:test` tests, so if you add vitest, `neocord test` stops with an error that lists this file until you switch it to [vitest's own imports](/docs/testing#which-runner-is-used).

## Typegen

Generate the route types and check the project:

```pm
run typecheck
```

This runs `neocord typegen`, which writes `.neocord/manifest.ts`, `.neocord/types.d.ts` and the entry files, then `tsc --noEmit`. Change `route="general/refresh"` to a route that does not exist and it fails to compile.

`neocord dev`, `neocord build` and `neocord test` also generate these files, so you only run typegen on its own when you want types without running anything. Run this to see the route table:

```pm
x neocord routes
```

## Run it

```pm
run dev
```

`neocord dev` syncs your commands to `DEV_GUILD_ID` and starts the bot. Type `/ping` in your server:

<DiscordPreview command="/ping" label="The ping reply in Discord">
  <DiscordText>Pong! Gateway latency is 42 ms.</DiscordText>
</DiscordPreview>

If nothing shows up, see [Troubleshooting](/docs/troubleshooting).

## Test

```pm
run test
```

`neocord test` validates every route and command payload, then runs your tests. It needs Bun on the machine, or vitest in your dependencies. Otherwise it stops with "No test runner found."

## Build and start

For production, build the bundle, register your commands globally, and start the sharding manager:

```pm
run build
run deploy
run start
```

| Step | What it does |
| --- | --- |
| `neocord build` | Writes `shard.js`, `manager.js` and `deploy.js` to `.neocord/build`. |
| `neocord deploy` | Registers commands with Discord, and skips the call when nothing changed. |
| `neocord start` | Launches the manager, which starts the shards. |

`neocord start` validates the environment, so `DISCORD_TOKEN` must be set. Global commands can take time to appear in Discord clients. See [Deploying commands](/docs/deployment/deploying-commands) and the [Production checklist](/docs/deployment/checklist).
